# Event log implementation plan

> For agentic workers: use superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Record every push, pop and restore as a timestamped event in SQLite and serve it as jsonl.

**Architecture:** `store.upsert` compares the incoming item with the stored row and appends events in the same
transaction. Items carry an optional device-clock `at`. `GET /api/log` renders the table as ndjson.

**Tech stack:** Bun, `bun:sqlite`, `bun:test`, plain JS client.

**Spec:** `docs/superpowers/specs/2026-11-18-event-log-design.md`

## Global constraints

- Times are integer ms since epoch in the database and in the API's item JSON; the log endpoint renders ISO-8601 UTC.
- `at` is optional on input. Missing: `ts` for a push, server clock otherwise. Later than the server clock: clamped.
- Old clients (no `at`) and old servers (ignore `at`) must keep working.
- Existing 66 tests keep passing, except assertions that pin the exact item shape, which gain `at`.

## Review focus

- An `at` in the far future (device clock wrong) must not produce a 4xx or a future event.
- Retrying the same PUT (offline resend, epoch reset) must not duplicate events.
- A database created before this change (no `at` column, no `events` table) must open and work.

### Task 1: Store events and `at`

**Files:** modify `server/store.ts`; test `server/store.test.ts`.

**Interfaces:**
- Produces: `Item` gains `at: number`; `ItemInput` gains optional `at?: number`;
  `openStore(path, opts?: { now?: () => number }): Store`;
  `Store.log(): LogEvent[]` where `LogEvent = { n: number; ts: number; at: number; op: "push" | "pop" | "restore"; id: string; text: string }`.

- [ ] Write failing tests: new live item logs one `push` (at = `ts` when no `at`); new removed item logs `push` then
      `pop`; live→removed logs `pop`; removed→live logs `restore`; identical resend logs nothing; `at` later than
      `now()` is clamped to `now()`; missing `at` on a pop uses `now()`; a non-integer `at` throws `ValidationError`;
      `ts` on events is `now()`; a database file created with the old schema (no `at` column) opens, keeps its
      items, and reports `at` equal to `ts`; events survive close and reopen of a file database.
- [ ] Run them; confirm they fail for the right reason.
- [ ] Implement: `events` table, guarded `ALTER TABLE items ADD COLUMN at INTEGER`, `now` option (default
      `Date.now`), event derivation inside the existing immediate transaction, `log()`.
- [ ] Update existing exact-shape assertions in `server/store.test.ts` to include `at`; run the whole suite.
